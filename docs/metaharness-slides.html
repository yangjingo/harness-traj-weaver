Meta-Harness

The Self-Improving Loop for AI-Coded Software

Four principles · Four skills · One hook

AI-coded software needs a self-reviewing harness, not just more tests
The Problem

LLMs write code,
but who reviews the reviewer?

  • 01 AI generates code in Claude Code sessions
  • 02 No trace between commit and the conversation that produced it
  • 03 Review is reactive — after code is already committed
  • 04 No feedback loop to improve the process itself
Without traceability, AI-generated code is a black box — you can't diagnose what you can't see
The Foundation

Four Principles

1

Filesystem as Memory

Full history on disk — no vector DB, no persistent memory. Just the filesystem.

2

Trace-Level Reasoning

Diagnose raw execution traces, not compressed summaries or aggregate scores.

3

Search-Set Feedback

All improvement signals from the search set. Never expose test-set results.

4

Self-Improving

Harness quality rises automatically as the underlying agent becomes more capable.

These aren't abstract virtues — each principle maps to a concrete skill that enforces it

Principle #2 — Trace-Level Reasoning

traj: See What the Agent Saw

Reads Claude Code JSONL sessions and generates a self-contained interactive timeline with TOC navigation, thinking blocks, tool call tracking, and skill usage highlighting.

python skills/traj/scripts/generate_traj.py \ --input ~/.claude/projects//.jsonl \ --output traj.html
Thinking blocks Tool calls Skill execs TOC nav
Don't read summaries — read the raw conversation. Thinking blocks reveal the agent's actual reasoning
Principle #3 — Search-Set Feedback

metric: Gate Quality Before Commit

Reads git diff and evaluates every change against the four Karpathy Principles — auto-detects over-engineering, drive-by edits, and missing assumptions.

P#PrincipleWhat it Checks
P1Think Before CodingAssumptions stated? Alternatives considered?
P2Simplicity FirstNo over-engineering? 200 lines → 50?
P3Surgical ChangesEvery line traces to the goal?
P4Goal-Driven ExecutionVerifiable completion criteria?
python skills/metric/scripts/generate_dashboard.py \ --diff HEAD --goal "Add user auth"
Code review should be pre-commit, automated, and principle-based — not a post-hoc human bottleneck
Principle #3 & #4 — Closing the Loop

survey: Human Judgment, Structured

Generates HTML-form questionnaires with auto-injected git history, CHANGELOG, and ROADMAP — so the reviewer sees full context before answering.

TypeTargetQuestions
qaIndividual skill UI/UX22 questions · 6 sections
human-loopMeta-Harness paradigm19 questions · 4 parts

Context injected: git log · git log -5 · CHANGELOG.md · ROADMAP.md

Feedback without context is noise — every survey embeds the git history that produced the change

Principle #1

Filesystem as Memory

.cache/ traces/ — execution traces (JSONL sessions) candidates/ — candidate harness outputs feedback/ — search-set evaluation results evals/ v0.1.0/ inputs/ session.jsonl — archived session for traj demo outputs/ traj.html — generated trajectory HTML meta-harness-survey.html — human feedback survey dashboard.html — code review results CHANGELOG.md — project version history ROADMAP.md — future direction (surfaced in surveys)

No database. No vector store. No persistent memory. Just the filesystem.

The filesystem is the ultimate audit trail — every artifact is versioned, readable, and diffable
Automation

Pre-Commit Hook: The Gate

Fires before every git commit — finds the current Claude Code session, runs traj + metric, and blocks if quality drops.

git commit │ ├─ 1. Find current Claude Code session JSONL │ (~/.claude/projects/<project>/<latest>.jsonl) │ ├─ 2. Generate traj.html from the session trace │ → .cache/feedback/traj-<session-id>.html │ ├─ 3. Run metric review on staged changes │ → .cache/feedback/review-<timestamp>.html │ ├─ 4. Show terminal summary │ └─ 5. Block commit if score < threshold
One hook. Installed in seconds. Every commit is now traced, scored, and archived — automatically

Get Started

Install the Harness

# 1. Install the pre-commit hook cp hooks/pre-commit .git/hooks/pre-commit chmod +x .git/hooks/pre-commit # 2. Enable strict mode (optional) git config metaharness.strict true git config metaharness.threshold 3.0 # 3. Commit as usual — the harness runs automatically git commit -m "my change"

That's it. Every commit is now traced, scored, and archived.

Two commands to install. Zero changes to your workflow. Instant quality gate on every commit
